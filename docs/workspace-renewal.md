# 프로젝트 워크스페이스 리뉴얼

홈을 이메일·생활 위젯 중심에서 프로젝트 현황과 지식 재사용 중심으로 변경했다. 기존 이메일·일정·투자·생활 위젯은 `/personal`에 유지한다.

| 화면 | 사용 흐름 |
| --- | --- |
| `/` | 운영 프로젝트 현황, 최근 지식, 프로젝트 브리프, AI 인계, 운영 체크포인트 |
| `/projects` | 호스트에서 발견한 프로젝트를 검색·상태·호스트로 필터링하고 운영 상세로 이동 |
| `/projects?view=briefs` | 배포 전 프로젝트도 브리프로 등록하고 열기·수정·AI 인계 |
| `/knowledge` | 제목·본문·AI 정리본 검색, 저장한 문서 열기 |
| `/knowledge/[id]` | 해당 문서 직접 수정, Markdown 복사·다운로드 |
| `/handoff` | AI 인계·기술 매뉴얼·학습 기록·프로젝트 브리프 작성 |

셸에 모바일 메뉴, 본문 건너뛰기, `Ctrl/⌘ K` 빠른 이동과 Escape 포커스 복귀를 제공한다. 사이드바 접힘은 기존 쿠키, 프로젝트 검색·필터는 URL에 유지한다. 작성 초안과 재시도 ID는 사용자·작성 맥락별 sessionStorage로 탭 안에서 복원하며 저장 완료 시 제거한다.

## 데이터와 상태

- 기존 `memos`·`memo_categories`를 사용한다. 선택한 문서 유형을 `workspace-handoff`, `workspace-manual`, `workspace-learning`, `workspace-project`로 명시 분류한다. 프로젝트 브리프는 제목 접두어를 지워도 분류가 유지된다.
- 요청 UUID로 중복 생성을 방지한다. 분류·생성은 한 트랜잭션이며, 재시도는 동일 소유자·동일 내용만 재사용한다. 수정은 문서 ID와 로그인 사용자로 한정하고 최초 원문은 보존한다. 편집을 시작한 본문·제목과 현재 값이 달라지면 덮어쓰지 않고 충돌을 알린다.
- 운영 프로젝트는 기존 전역 호스트 카탈로그, 브리프와 지식은 로그인 사용자 소유다. 운영 프로젝트와 브리프를 이름으로 자동 병합하지 않는다. 지식 검색은 텍스트 검색이다.
- 컨테이너 실행·확인 필요·미관측·조회 실패를 구분한다. 실행 상태는 애플리케이션 건강 상태나 배포 성공을 보장하지 않는다.
- 인계 대상 AI로 자동 전송하지 않는다. 저장 문서는 기존 메모의 AI 액션 추출·다이제스트 대상이다. 학습 기록은 지식 기록이며 모델 학습 실행을 의미하지 않는다.
- 새 DB 테이블·마이그레이션·외부 의존성은 없다. 홈/목록은 본문 없이 요약 필드만 조회하며, 목록 최대 개수는 기존 공통 한도를 따른다.

## 검증

- 전체 테스트 1,841개, 타입 검사, 프로덕션 빌드 통과. 린트 오류 0개, 기존 테스트의 미사용 인자 경고 3개.
- 로그인된 로컬 브라우저에서 모바일 메뉴·상태 필터·브리프 등록·지식 검색·문서 저장 및 동일 ID 수정·복사·Markdown 파일 다운로드·뒤로가기 초안 복원를 확인했다. 단축키가 검색 입력에 초점을 주고 Escape가 트리거로 돌려준다.
- 테스트 DB는 별도 로컬 PostgreSQL을 사용했다. 운영 배포는 실행하지 않았다.

## 리뷰 판정

- Claude/Grok의 재저장 중복, 재시도 안전성, 정확한 편집 진입점, 브리프 디렉터리 누락을 반영했다. 분류 라벨·본문 없는 목록 조회·잘못된 필터·글자 수 안내도 보완했다.
- Gemini의 검색/필터 이동 방식 불일치를 반영해 클라이언트 필터는 native History API로 통일했다. 후속 리뷰의 “History API는 검색 훅을 갱신하지 않는다”는 지적은 설치된 Next.js `app-router.js`의 패치와 실제 필터 동작을 확인해 기각했다.
- UUID/호스트 이름/React 버전/isStale 의미에 대한 추측은 실제 스키마·라우트·패키지·groupByProject로 대조했다. UUID PK, 고유 호스트 이름, React 19, 컨테이너가 없는 그룹이라는 기존 계약을 유지한다.

- 후속 리뷰의 수정된 문서 재시도 충돌, 뒤로가기 초안 유실, 편집 덮어쓰기, HTTP에서의 UUID 생성, 동일 URL 오류 재조회 문제를 보완하고 회귀 테스트로 확인했다. feature 간 import는 이 저장소 ESLint가 허용하는 기존 예외이며 구조 위반이라는 지적은 기각했다. 브리프 조회 실패는 배너에서 설명하며, 생성순 목록의 수정일 표시는 정렬 기준을 주장하지 않는다.
